# The release keystore was committed once, in a public repository

## What happened

`NetPilotMobile/keystore.properties` and `NetPilotMobile/netpilot-release.jks` were tracked by
git in commit `18a906c`, which was pushed to the public repository
`github.com/Ekkh1300/NetPilot`. Both files have been removed from the current tree and are
git-ignored, and the commit was rewritten so neither file appears anywhere in master's history.

That is not enough, and this note exists so the reason is not lost.

## Why it still matters

A blob that was pushed to a public host cannot be unpublished. GitHub keeps unreachable objects
alive for a while, forks and caches may already hold them, and anyone who saw the push can
retrieve it by object id. History rewriting removes the path; it does not remove the bytes.

Anyone holding this keystore can produce an APK that Android installs as though it came from
us, with our package name and our signature. That is enough to serve a modified app to existing
users, and it cannot be withdrawn by publishing a new version.

## What to do

**Generate a new keystore and use it from now on.** The old one is finished.

```powershell
keytool -genkeypair -v -keystore netpilot-release.jks -alias netpilot `
        -keyalg RSA -keysize 2048 -validity 10000
```

Put the new credentials in `NetPilotMobile/keystore.properties`, which is ignored, or export
them as `NETPILOT_STORE_FILE`, `NETPILOT_STORE_PASSWORD`, `NETPILOT_KEY_ALIAS` and
`NETPILOT_KEY_PASSWORD` - which is what CI should use, so the credentials never touch a disk
on a build machine.

**Then move Play Console to it.** In Google Play Console: Setup, App signing, choose the new
key to upload, and follow the reset instructions. Google keeps the old signing key on file
precisely for this case, so the app listing does not have to be recreated.

**Never commit the replacement.** `.gitignore` now covers `*.jks`, `*.keystore`, `*.p12` and
`*.pfx` as well as `keystore.properties`, and `keystore.properties.example` documents the shape.

## Why the passwords were the weakest link anyway

The committed file held `storePassword=netpilot`, `keyAlias=netpilot`, `keyPassword=netpilot`.
Even before publication those were guessable from the project name, so the keystore's exposure
was not the only problem - the credential protecting it was. A new keystore with a password
generated by `keytool` and stored only in CI secrets closes both.
