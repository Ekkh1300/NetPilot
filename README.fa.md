## اپ اندروید

* **داشبورد سلامت شبکه** — یک نمره برای کیفیت DNS، تأخیر، پاکت‌لاس و پایداری اتصال، کنار
  نمودار ترافیک زنده و جمع کل دانلود و آپلود.
* **مدیریت DNS** — سازنده‌های آماده به‌علاوهٔ سرور سفارشی خودت؛ هر کدام با تأخیر پاسخ
  سنجیده می‌شود و یک‌دانگه به حالت قبل برمی‌گردد.
* **مانیتور زنده** — نمودار دانلود و آپلود از بازهٔ ثانیه‌ای تا یک‌ساعته.
* **مصرف هر برنامه** — چه چیزی واقعاً دارد دانلود می‌کند، مرتب بر اساس حجم.
* **محدودکنندهٔ اینترنت** — سقف دانلود و آپلود برای هر برنامه، یا مسدود کردن کامل. سقف‌ها
  واقعاً در تونل اعمال می‌شوند، نه فقط نمایشی.
* **محدودیت زمان‌بندی‌شده** — قانون‌هایی که در ساعت‌های مشخص روز اعمال می‌شوند.
* **پروفایل‌ها** — یک‌بار بساز، خروجی بگیر، هرجا خواستی برگردان.
* **ابزارهای شبکه** — ping، nslookup، پاک‌سازی کش DNS و بازنشانی، داخل خود اپ.
* **تونل محلی** — دو حالت: «فقط DNS» (فقط پرس‌وجوها از مسیر دلخواه) و «تونل کامل» (کل ترافیک).
  اگر مسیر از کار بیفتد، خودکار به مسیر عادی برمی‌گردد؛ اینترنت گوشی قطع نمی‌شود.
* **تونل گوشی → PC** — تونل گوشی را با وای‌فای مشترک، هات‌اسپات، اشتراک USB یا کابل adb
  به رایانهٔ ویندوز بده.

رابط کاربری کاملاً دوزبانه (انگلیسی/فارسی با راست‌به‌چپ)، تم تیره، بدون هیچ دسترسی
موقعیت مکانی، فایل یا دوربین. دسترسی «آمار مصرف برنامه» فقط برای جدول مصرف لازم است و
اختیاری می‌ماند.

## اپ ویندوز

همان ابزارها به‌شکل دسکتاپ: داشبورد با نمره‌دهی سلامت، مدیریت DNS با بکاپ و بازگردانی،
مانیتور زنده، مصرف هر برنامه، محدودکنندهٔ اینترنت (سقف آپلود با سیاست واقعی QoS ویندوز،
سقف دانلود با token bucket)، محدودیت زمان‌بندی‌شده و زمانی، تاریخچهٔ رویداد و اتصال،
ابزارهای شبکه، فهرست کارت‌های شبکه، و صفحهٔ **تونل گوشی → PC** که با اپ اندروید جفت می‌شود.

اپ ویندوز با دسترسی مدیر اجرا می‌شود و خودش قانون فایروالش را می‌سازد و هنگام حذف پاکش می‌کند.

## تونل گوشی → PC چطور کار می‌کند

```
اپ اندروید  ──HTTP :8787 (کنترل)──▶  پل ویندوز
اپ اندروید  ◀──HTTP :8788 (داده)───   پروکسی ویندوز
                                          │
                                          ▼
                                   تونل گوشی ──▶ اینترنت
```

* رایانه روی **۸۷۸۷** گوش می‌دهد؛ گوشی یک پروکسی کوچک HTTP روی **۸۷۸۸** اجرا می‌کند که
  درخواست‌های `CONNECT` را بایت‌به‌بایت تونل می‌کند و ویندوز WinHTTP/WinINET را به آن می‌چرخاند.
* هر سوکتی که این پروکسی باز می‌کند با `VpnService.protect()` دوباره **داخل تونل** برده می‌شود؛
  اپ پکیج خودش را از تونل کنار می‌گذارد تا در حلقه گرفتار نشود، پس بدون این کار رایانه به‌جای
  IP وی‌پی‌ان گوشی، به IP واقعی گوشی می‌رسید.
* چهار مسیر پشتیبانی‌شده: وای‌فای مشترک، هات‌اسپات گوشی، اشتراک USB، و
  `adb reverse tcp:8787 tcp:8787` برای توسعه.
* اندروید در هر لحظه فقط یک اپ VPN را اجازه می‌دهد: یا تونل خود نات‌پایلوت روشن است (حالت
  فول‌تونل)، یا یک اپ دیگر. در هر دو حالت رایانه از همان VPN استفاده می‌کند.

**چه چیزی نیست:** پل رایانه یک پروکسی است، نه یک gateway لایهٔ IP. فقط برنامه‌هایی که پروکسی
سیستم را می‌خوانند (مرورگرها و بیشتر اپ‌ها) از آن عبور می‌کنند؛ هر چیزی که سوکت خام یا UDP/QUIC
باز می‌کند عبور نمی‌کند. اندروید هم هیچ‌وقت بسته‌های رسیده از وای‌فای را وارد TUN یک اپ
نمی‌کند، برای همین «حالت route» ذاتاً کار نمی‌کند.

## ساخت پروژه

### اندروید

```bash
cd NetPilotMobile
./gradlew lintDebug testDebugUnitTest assembleDebug assembleRelease
```

* `minSdk 26` (اندروید ۸.۰) · `targetSdk 36` · Kotlin + Compose · Java 17
* APK یکپارچه: `arm64-v8a`، `armeabi-v7a`، `x86`، `x86_64`

**امضا:** کلید امضا در این ریپو **نیست**. `keystore.properties.example` را به
`keystore.properties` کپی و پر کن، یا متغیرهای محیطی `NETPILOT_STORE_FILE`،
`NETPILOT_STORE_PASSWORD`، `NETPILOT_KEY_ALIAS` و `NETPILOT_KEY_PASSWORD` را ست کن (روش
پیشنهادی برای CI). بدون هیچ‌کدام هم `assembleRelease` ساخته می‌شود، فقط APK امضا نمی‌شود.

### ویندوز

```powershell
dotnet build NetPilot\NetPilot.csproj
```

* .NET 8، WPF، `net8.0-windows` · ویندوز ۱۰ نسخهٔ ۱۶۰۷ به بالا و ویندوز ۱۱
* برای نصب و اجرا به دسترسی مدیر نیاز دارد

نصب‌کننده (self-contained، روی سیستم مقصد نیازی به نصب .NET نیست):

```powershell
powershell -ExecutionPolicy Bypass -File installer\build.ps1
# -> dist\NetPilot-Setup.exe
```

## تست

```powershell
# همه‌چیز: تست‌های ویندوز، تست‌های اندروید به‌همراه lint، و بررسی اینکه اجرای تست‌ها
# چیزی از فایروال، پروکسی یا مسیریابی سیستم را تغییر نداده باشد.
powershell -ExecutionPolicy Bypass -File NetPilot\Tools\verify.ps1

# تست‌های ویندوز را ادمین اجرا کند - دو مجموعه، DNS واقعی و سیاست QoS واقعی ویندوز را
# تغییر می‌دهند و بعد همه‌چیز را برمی‌گردانند.
powershell -ExecutionPolicy Bypass -File NetPilot\Tools\verify.ps1 -Elevated

# تست کامل نصب‌کننده: نصب ← اجرا ← حذف
powershell -ExecutionPolicy Bypass -File NetPilot\Tools\verify.ps1 -Installer
```

| مجموعه | کجاست | تعداد |
|---|---|---|
| تست واحد اندروید | `NetPilotMobile/app/src/test/` | ۹۲ |
| تست واحد ویندوز | `NetPilot.Tests/` | ۴۳ |
| تست کامل نصب‌کننده | `NetPilot/installer/test.ps1` | نصب / اجرا / حذف |

مجموعهٔ تست ویندوز شامل تست‌های یکپارچه‌ای است که با پشتهٔ شبکهٔ واقعی کار می‌کنند: یک
resolver را اعمال می‌کنند و مطمئن می‌شوند آداپتور بایت‌به‌بایت به حالت اول برگشته، و یک
سیاست QoS واقعی ویندوز می‌سازند و حذف می‌کنند.

## نکات امنیتی

* **`keystore.properties`، `*.jks` و `*.keystore` را هرگز commit نکن.** هر کسی کلید امضا را
  داشته باشد می‌تواند آپدیتی بسازد که گوشی‌ها آن را به‌عنوان نات‌پایلوت نصب می‌کنند. هر دو در
  `.gitignore` هستند؛ اگر قبلاً push شده‌اند، کلید را عوض کن.
* توکن پل رایانه در هر بار اجرای اپ بازتولید می‌شود و فقط در ازای کد شش‌رقمی نمایش‌داده‌شده
  در رابط کاربری صادر می‌شود؛ پنج تلاش ناموفق در دقیقه بعد از آن باید کد دوباره صادر شود.
* درخواست‌های بدون احراز هویت پیش از اجرای هر هندلری رد می‌شوند.
